## Deployment Notes — What's Actually Live, And What To Reuse

The app is deployed and reachable end-to-end for testing. Concrete state:

**Frontend:** https://ttt-scavenger-hunt-v3.pages.dev (Cloudflare Pages, free tier)
**Backend:** https://173-230-128-241.nip.io (Linode 2GB VPS, Docker Compose, Caddy reverse proxy)
**Admin login:** kemperdesignservices@gmail.com / 4173 (weak on purpose for a private test box — change before this ever becomes public)

Working config, in case the next project needs the same stack:

- **Cloudflare Pages + Next.js**: build command `npx @cloudflare/next-on-pages@1`, output dir `.vercel/output/static`, root dir = your frontend folder. Needs a `.npmrc` with `legacy-peer-deps=true` (Cloudflare's own toolchain has an internal version conflict otherwise) and the `nodejs_compat` compatibility flag set on *both* Production and Preview environments (Settings → Runtime).
- **No domain was purchased.** Backend gets a real hostname for free via `nip.io` (wildcard public DNS: `173-230-128-241.nip.io` resolves straight to that IP, no signup needed) plus Caddy for automatic free HTTPS. This was required, not optional — Cloudflare Workers refuse to `fetch()` a bare IP address.
- **GitHub repo had to be public**, not private, because Vercel's Hobby tier forces a login wall on private-repo deployments that can't be disabled without a paid plan. (We ultimately moved off Vercel to Cloudflare Pages anyway, which doesn't have this restriction — but the repo is already public and there's no reason to flip it back.)
- A full reusable write-up of every deployment gotcha we hit (Cloudflare build settings, the bcrypt/passlib version trap, SQLAlchemy circular-import patterns, the AuthGuard-guards-its-own-login-page loop, etc.) is saved separately at `deployment-playbook-notes.md` on the Desktop — read that before starting the next project's deployment.
