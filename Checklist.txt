Persists message history to `conversation_messages`, auto-completes at `min_exchanges`, awards points server-side. Live in production.
- [x] Ollama removed from the live code path entirely — every function that called it (`app/ai/rag.py` embeddings, `app/ai/ingest.py` embeddings, the legacy `/api/v1/characters/chat` endpoint) now uses OpenAI instead (`text-embedding-3-small` for embeddings, truncated to 768 dims to match the existing Qdrant collection; `gpt-4o-mini` for chat, same as the challenge-based endpoint). `OLLAMA_*` settings kept as unused/harmless so old `.env` files don't break config parsing.

## Deployment Notes — What's Actually Live, And What To Reuse

The app is deployed and reachable end-to-end for testing. Concrete state:

**Frontend:** https://ttt-scavenger-hunt-v3.pages.dev (Cloudflare Pages, free tier)
**Backend:** https://173-230-128-241.nip.io (Linode 2GB VPS, Docker Compose, Caddy reverse proxy)
**Admin login:** kemperdesignservices@gmail.com / 4173 (weak on purpose for a private test box — change before this ever becomes public)

Working config, in case the next project needs the same stack:

- **Cloudflare Pages + Next.js**: build command `npx @cloudflare/next-on-pages@1`, output dir `.vercel/output/static`, root dir = your frontend folder. Needs a `.npmrc` with `legacy-peer-deps=true` (Cloudflare's own toolchain has an internal version conflict otherwise) and the `nodejs_compat` compatibility flag set on *both* Production and Preview environments (Settings → Runtime).
- **No domain was purchased.** Backend gets a real hostname for free via `nip.io` (wildcard public DNS: `173-230-128-241.nip.io` resolves straight to that IP, no signup needed) plus Caddy for automatic free HTTPS. This was required, not optional — Cloudflare Workers refuse to `fetch()` a bare IP address.
- **GitHub repo had to be public**, not private, because Vercel's Hobby tier forces a login wall on private-repo deployments that can't be disabled without a paid plan. (We ultimately moved off Vercel to Cloudflare Pages anyway, which doesn't have this restriction — but the repo is already public and there's no reason to flip it back.)
- A full reusable write-up of every deployment gotcha we hit (Cloudflare build settings, the bcrypt/passlib version trap, SQLAlchemy circular-import patterns, the AuthGuard-guards-its-own-login-page loop, etc.) is saved separately at `deployment-playbook-notes.md` on the Desktop — read that before starting the next project's deployment.

## Future App Idea: Wine Passport (separate concept, not part of TimeQuest)

A personal wine-tracking app — logging bottles tried, where and when, with
ratings and photos. Distinct product from TimeQuest; captured here so the
idea isn't lost.

**Core features (as requested):**
- [ ] Wine log — track every wine tried, with date and notes
- [ ] Location tagging — where each wine was had (restaurant, winery, home, etc.)
- [ ] Rating system — personal score/review per wine
- [ ] Label photo capture — snap a photo of the bottle label per entry
- [ ] "Where to buy" lookup — locate retailers or sources carrying a given wine

**Additional feature ideas:**
- [ ] Label OCR — auto-extract producer/vintage/varietal from a label photo instead of typing it in
- [ ] Barcode/QR scan — quick lookup against a wine database instead of manual entry
- [ ] Tasting notes template — structured fields (nose, palate, finish, tannins, acidity) beyond a free-text note
- [ ] Food pairing suggestions — per wine or varietal
- [ ] Personal cellar/inventory tracking — bottles owned vs. bottles already had, with quantity and storage location
- [ ] Drink-window reminders — notify when an aging bottle is approaching its ideal drinking window
- [ ] Price tracking — what was paid vs. current market price
- [ ] Wine region exploration — map view of regions/wineries visited or wines tried from
- [ ] Social features — share tasting notes or a passport profile with friends, compare ratings
- [ ] Wishlist — wines to try, separate from the log of wines already had
- [ ] Achievement badges — e.g. "tried 10 varietals," "visited 5 regions" (same pattern as TimeQuest's badge system)
- [ ] Export/share the passport — PDF or shareable link of a personal wine history
- [ ] AI sommelier chat — ask for recommendations based on logged preferences (same pattern as TimeQuest's AI historian characters)
